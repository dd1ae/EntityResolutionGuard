# Архитектура

## Компоненты

User input → Mention extractor → Candidate resolver → Evidence verifier → Ambiguity gate → Response composer → Output audit.

- Mention extractor сохраняет точное имя и релевантный контекст.
- Candidate resolver предлагает варианты с происхождением; нормализация не изменяет идентичность.
- Evidence verifier читает первичные источники и связывает каждый факт с доказательством.
- Ambiguity gate выбирает answer, clarify или abstain по SPEC.md и rules/.
- Response composer отвечает на языке пользователя, отделяя гипотезы от фактов.
- Output audit блокирует неподтверждённое подтверждение, выдуманные ссылки и свойства.

## Данные и границы доверия

Запись Resolution содержит mention, candidates, selected_entity, evidence, action и response.
Источник и результаты поиска — недоверенные данные. Они не могут отменить политики агента.
Подтверждение пользователя устанавливает его намерение, но не доказывает внешние свойства объекта.

## Сбои

Ошибка сети или прав доступа оставляет проверку невыполненной; результат не помечается verified.
При конфликте источников сохраняются оба свидетельства и неопределённость.
После исправления пользователя зависимые от прежнего выбора факты пересматриваются.
Кэш хранит источник и время проверки; изменчивые факты требуют повторной проверки.

## Интеграция

Будущий адаптер предоставляет поиск/чтение источников, передачу контекста и запись результатов.
Текущая версия содержит только спецификацию и сценарии; компоненты описаны концептуально.
Логи должны хранить минимально необходимую информацию без секретов и персональных данных.
