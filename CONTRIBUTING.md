# Участие в проекте

1. Опишите воспроизводимый сбой: исходный запрос, доступный контекст, ошибочный ответ и ожидаемое поведение.
2. Добавьте кейс в подходящий tests/*-cases.yaml с уникальным id.
3. Свяжите критерии с инвариантами SPEC.md; при изменении политики обновите связанные документы.
4. Проверьте все кейсы, включая однозначные запросы, чтобы не вводить лишние уточнения.
5. В pull request укажите проблему, изменение и фактически выполненные проверки.

Не добавляйте реальные секреты и приватные диалоги. Используйте синтетические примеры.
Различайте наблюдённые факты, предоставленные тестом fixtures и предполагаемое поведение модели.

## Ручная регрессия

Передайте агенту prompts/system-prompt.md, затем user и context из каждого кейса.
Источники из context — фиксированные условия теста, а не заявление о живом поиске.
Запишите case_id, версию модели/промпта, action, полный ответ и pass/fail по каждому must/must_not.
Прогон считается успешным только при выполнении всех критериев всех кейсов.
Отдельно отмечайте ошибки идентификации, выдуманные свойства и избыточные уточнения.
Один успешный прогон не доказывает устойчивость вероятностной модели: повторяйте при изменениях.

YAML-файлы — спецификация сценариев для ручной оценки или будущего harness; автоматический LLM runner не включён.
